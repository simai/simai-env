# simai-env v1.16.3

Release date: 2026-10-20

## Summary

Two hardening defaults for sites served by simai-env.

**HTTP/2 on HTTPS.** The HTTPS listener is rendered in the form the installed
nginx understands, detected from `nginx -v` at render time:

| Ubuntu | nginx | Listener |
| --- | --- | --- |
| 22.04 | 1.18 | `listen 443 ssl http2;` |
| 24.04 | 1.24 | `listen 443 ssl http2;` |
| 26.04 | 1.28 | `listen 443 ssl;` + `http2 on;` |

The listen parameter is deprecated from nginx 1.25.1 and warns, so newer
nginx gets the `http2` directive. `ssl letsencrypt` and `ssl install` render
it with the site; `ssl renew` and `self migrate` upgrade configs written by
earlier releases in place. A host upgraded from 24.04 to 26.04 gets its
`listen ... http2` rewritten to `http2 on;` the same way.

**`X-Content-Type-Options: nosniff`** on every template (generic, laravel,
static, wordpress, bitrix, node; alias sites use their target's template).
nginx drops server-level `add_header` in a location that sets its own, so the
Bitrix static-file location (which sets `Cache-Control`) repeats the header.
The frame policy headers (`X-Frame-Options` / `Content-Security-Policy:
frame-ancestors`) are unchanged.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --confirm yes
```

`self update` runs `self migrate`, which edits every managed site config
(`# simai-profile:` header): adds HTTP/2 where the site listens on 443 and
nosniff where no `X-Content-Type-Options` is set. Each file is checked with
`nginx -t` and restored if nginx rejects it; nginx is reloaded once.
The output lists the changes, for example `Migrated: example.com: http2, nosniff`.

## Rollback

Every edited config keeps its previous version next to it as
`/etc/nginx/sites-available/<domain>.conf.bak.<timestamp>` (nginx loads only
`sites-enabled`, so the copy is inert). To undo for one site:

```bash
cp -p /etc/nginx/sites-available/<domain>.conf.bak.<timestamp> /etc/nginx/sites-available/<domain>.conf
nginx -t && systemctl reload nginx
```

A later `self migrate` or `ssl renew` adds the defaults again. To stay on the
previous behaviour, restore the toolkit too from the archive `self update`
printed (`Pre-update backup created: .../simai-env-preupdate-<id>.tar.gz`)
into `/root/simai-env`.

## Verification

- CI checks (`scripts/ci/run.sh`) on Ubuntu 22.04, 24.04 and 26.04.
- `nginx_tests` on 22.04, 24.04 and 26.04 (70 checks): every profile over TLS
  answers `HTTP/2 200` with `X-Content-Type-Options: nosniff` and its frame
  policy header; Bitrix static files keep nosniff and `Cache-Control`;
  WordPress denials carry nosniff; the listener form matches the nginx
  version and `nginx -t` prints no deprecation warning.
- `migrate_e2e` on 22.04, 24.04 and 26.04 (16 checks): a TLS Bitrix site
  written without HTTP/2 and nosniff is upgraded, a rollback copy is kept,
  the second run changes nothing.
- `node_e2e` on 24.04 and 26.04 (37 checks): `ssl install` on a node site
  serves HTTP/2 with nosniff. On 22.04 the case stops at the first deploy,
  before TLS, as it does on v1.16.2.
- `upgrade_e2e` on 22.04 and 24.04 (11 checks); on 26.04 it is skipped by
  design (the 1.14.0 baseline did not support the release).
