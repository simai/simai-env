# simai-env v1.34.0

Release date: 2026-11-02

## Summary

Larena Panel stage 5.4: a site's own scheduled commands.

- **Cron jobs per site.** `cron:job-add {domain, schedule, command}` adds a
  command on a five-field schedule; `cron:job-enable`, `cron:job-disable`
  and `cron:job-remove` take its `id`. `cron:list {domain}` shows the jobs
  with their last run (`simai-cron-jobs/1`).
- **Run records.** Each run keeps its start, end, exit code and the last 50
  lines of output; `cron:job-runs {id, limit}` returns the last runs
  (`simai-cron-runs/1`). The last 50 runs per job are kept.
- **Safe by default.** Jobs run as the site user in the site directory,
  never as root; a run still going makes the next one skip; the command is
  stored outside the cron file. Owners manage jobs of their own sites only.
- `site remove` takes the jobs along; `site isolate` moves them to the new
  user.

**Security fix.** Removing an SFTP account left its access entries on the
site directories, so the next account created with the same numeric id
(often the user of a new site) could read and write every site. `access
remove` now drops them; creating a site user, owner or SFTP account drops
entries left by an older version. To check a server now:
`getfacl -Rcp /home/simai/www | grep -E '^(default:)?user:[0-9]+:' | sort -u`
should print nothing.

Recorded panel answers move to set 10.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --check-sites yes --confirm yes
```

## Verification

- `panel_e2e`: owners add, disable, enable and remove jobs of their own
  sites; another owner's site and unknown ids are refused; bad schedules and
  commands are refused; a job runs as the site user, records exit code and
  output, and skips while a run is going; isolation and site removal.
- `panel_e2e`: no access entries remain after SFTP accounts are removed;
  `iso_e2e` after it.
- Ubuntu 22.04, 24.04 and 26.04.
