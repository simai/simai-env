# simai-env v1.25.0

Release date: 2026-10-30

## Summary

Larena Panel (package `larena/env`, repository `simai/larena-env`) is
installed and updated by simai-env. Until now `panel install` with a build
created a bare site and deployed into it, which left a real Laravel
application without its requirements, `.env`, `APP_KEY` or migrations.

- A build is now attached with `site adopt`: the packages and PHP extensions
  of `.simai/app.json` and `composer.json`, `.env` from the build's own
  `.env.example` with `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` and
  the site's database values, `APP_KEY`, migrations, workers and the
  scheduler. The same source is then deployed, so the panel has a release to
  roll back to.
- A build that does not answer its health path is not installed: the site,
  its files and its database are removed again, and the server is left as it
  was.
- `panel update --archive F --sha256 S` (or `--git/--ref`) updates the panel:
  `backup data` first, then a deploy that migrates before the switch and
  keeps the current release if anything fails. A release that does not answer
  is rolled back; the database is not rolled back, which is what the backup
  is for. `.env`, the database and `storage/` survive an update.
- Installing a build over an installed build is refused and points at
  `panel update`; the placeholder is still replaced in place.
- New site databases grant `REFERENCES`: without it MySQL refuses the foreign
  keys of Laravel migrations (error 1142). Existing grants are not changed.
- `site adopt` treats the manifest's PHP as the minimum it is: on an Ubuntu
  release that ondrej/php does not cover yet (26.04) it uses that release's
  own PHP when it is new enough, instead of failing.
- simai-env texts call the panel Larena Panel. The `panel` command, its
  options and the gateway are unchanged.

```bash
sudo /root/simai-env/simai-admin.sh panel install --domain panel.example.com \
  --archive larena-panel-1.0.0.tar.gz --sha256 <hex> --ssl-email ops@example.com --confirm yes
sudo /root/simai-env/simai-admin.sh panel update --archive larena-panel-1.1.0.tar.gz --sha256 <hex> --confirm yes
```

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --confirm yes
```

## Verification

- The real build `larena-panel-0.1.0.tar.gz` on the local stand: install,
  first administrator through the one-time link (the line leaves `.env`),
  sign-in, `/admin/server` listing the stand's sites through the gateway,
  `panel update` with the administrator still signed in, rollback, and a
  broken update returning to the release that was serving.
- `panel_install_e2e` (60 checks): the build installed through adopt with
  APP_KEY, production `.env`, database and releases; a build that does not
  answer leaves nothing; `panel update` with its backup, the refusals without
  a source or without a panel, and the rollback of a broken release.
- `panel_e2e` (gateway) unchanged.
- CI on Ubuntu 22.04, 24.04 and 26.04.
