# simai-env v1.30.0

Release date: 2026-11-01

## Summary

The first part of Larena Panel stage 4 ("peace of mind") and the SFTP
accounts left from stage 3:

- **SFTP accounts.** An owner or administrator creates an SFTP account for
  one site with a public key (`access:create-project {domain, login,
  pubkey}`); the account sees only that site, as `/site`, and has no
  password at all. Keys are added, and accounts disabled, enabled and
  removed, by login; the gateway checks that the account belongs to the
  owner's site. Global accounts and passwords are not reachable from the
  panel. `access:list` shows the accounts without passwords or keys.
- **Checked backups.** `backup:data-schedule {verify: yes}` checks the newest
  copy after every scheduled backup, with a restore test when there is a
  database dump. Each site carries `last_verify {at, ok, backup,
  restore_test}`.
- **Backups from the start.** `site:add` gives a new site the daily backup
  (03:30, keep 7) unless `backup: no`.
- **Certificates.** `certificate.last_renew {at, ok}` tells whether the last
  renewal worked. Renewals now go one certificate at a time, so a failure is
  recorded for the certificate it belongs to.
- **Panel scheduler.** `panel status` shows whether the panel's own
  `schedule:run` entry is installed; it follows `"scheduler": true` in the
  panel build's `.simai/app.json`.

Fixes on the way:

- `site remove` left the site's backup schedule behind; the nightly job then
  failed for a site that no longer existed.
- A project SFTP account on an isolated site granted the shared `simai`
  account access to that site; it now grants only the user the site runs as.
- `access enable` could not re-enable an account without a password.

Recorded panel answers move to set 6 (57 files).

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --confirm yes
```

`self migrate` (run by the update) switches the renewal cron to `ssl
renew-due` and installs the renewal record hook.
