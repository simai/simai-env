# simai-env v1.17.0

Release date: 2026-10-20

## Summary

Sites are built in CI and deployed to the server by a key that can deploy
one site and nothing else. Static sites behave like GitHub Pages.

- **Static deploys from CI artifacts.** `site deploy --archive F --sha256 S`
  works for profile static. The artifact is the document root;
  `<root>/public` becomes a symlink to `current`, so nginx and the ACME
  webroot never change and certificates keep renewing. After the switch the
  health path from the artifact's `.simai/app.json` (default `/`) is
  requested through nginx; a failing release returns to the previous one and
  is kept as `releases/<id>-failed`.
- **GitHub Pages behaviour.** `/dir` -> `/dir/`, `/dir/` -> `dir/index.html`,
  `/name` -> `name.html`, `404.html` as the error page, `200.html` as the
  single-page-app fallback, underscore directories served, extensionless
  files as `text/plain`. Caching: HTML `no-cache`; file names with a content
  hash (12+ hex digits) `max-age=31536000, immutable`; other files
  `max-age=600` with ETag/Last-Modified. gzip for text types.
- **Per-site CI deploy keys.** `site deploy-key-add/list/remove`. A key logs
  in as `simai-deploy` and its forced command runs the deploy gate (one sudo
  rule), which accepts only `deploy-artifact <sha256>` (archive on stdin),
  `deploy-git <commit>` (keys added with `--git`), `status` and `rollback`
  for that site; no shell, TTY or forwarding; refusals are logged. Workflow
  step and secrets: `docs/operations/ci-deploy.md`.
- **Redirects.** `site redirect-add/remove/list` for exact paths
  (`/` -> `/ru/`), kept across re-renders such as `ssl install`; profile
  `redirect` for whole domains (path and query kept, ACME still answered).
- **Archive safety.** Symbolic links leaving the release are refused;
  archives are limited to `SIMAI_DEPLOY_MAX_ARCHIVE_MB` (default 1024 MB
  packed, four times that unpacked).

## Behaviour changes

- New static sites no longer answer unknown paths with `/index.html`: they
  return 404 (or `404.html`). A single-page app ships `200.html`. Existing
  static sites keep their configuration until it is re-rendered.

## Fixes

- `site deploy` silenced its own stderr after taking the deploy lock
  (`exec 7>file 2>/dev/null`): errors and progress reached only the log
  file. The errexit lint now rejects the pattern.
- Two deploys within one second shared one release directory; the second
  one now gets `<timestamp>-2`.
- The deploy summary checks the site through nginx and follows its
  redirects (HTTP -> HTTPS).
- The container suite: `migrate_e2e` no longer leaves a site named like the
  one `iso_e2e` creates.

