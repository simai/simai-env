# simai-env v1.12.78

Release date: 2026-08-03

## Summary

Bitrix restore preparation now validates every uploaded backup volume before
the operator is sent to `restore.php`. The command detects the Bitrix
multi-volume metadata in the base archive, verifies that every numbered part is
present and non-empty, and runs a gzip integrity check on each volume.

If the archive has not been uploaded yet, `restore-ready` prints the upload and
validation steps. A missing or corrupt part fails closed and names the first
bad file. The browser restore URL appears only after the archive passes.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update
```

Recommended restore sequence:

1. prepare the Bitrix site and `restore.php`;
2. upload the base archive and every numbered volume;
3. run `simai-admin.sh bitrix restore-ready --domain <domain>` again;
4. open the printed restore URL only after the archive status is `ready`;
5. complete the wizard and run `bitrix finalize`.

`--archive none` remains an explicit advanced bypass for operators who have
validated the source by another trusted method.

## Verification

- generated valid two-volume Bitrix fixture;
- missing-volume and truncated-volume regressions;
- restore-ready output and command option smoke checks;
- Bash syntax, ShellCheck, repository regression suite, and Linux command
  registry dispatch harness.

## Rollback

The change only adds a preflight check and does not mutate uploaded archives.
Rolling back to v1.12.77 restores the previous behavior, where the operator can
open `restore.php` without archive integrity validation.
