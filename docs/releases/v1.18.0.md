# simai-env v1.18.0

Release date: 2026-10-21

## Summary

Applications that ship a static build plus an API (the SIMAI playground) run
as one node site: nginx serves the build, the service answers only its
routes, and every path keeps the headers and caching the application needs.

- **Static root with service routes.** `static`, `routes`, `headers`
  (named sets), `page`, `locations`, `cache`, `deny`, `release_header` and
  `gzip_types` in `.simai/app.json`. `lib/app_routes.py` validates them
  (header names from an allowlist; no quotes, backslashes, braces or `$`
  references in values; `$` only as a regex anchor) and renders
  `/etc/nginx/simai-app/<domain>/routes.conf` and an http-level maps file.
  Deploys and rollbacks render the routes of the release being switched and
  run `nginx -t` before the switch is kept; a failing release returns to the
  previous one together with its routes.
- **Port and paths under the application's names.** `port_env`/`host_env`
  (`API_PORT`, `API_HOST`) and `{port}`, `{state}`, `{root}` in `env` values.
- **`site paths-allow`.** Serve only exact files and prefixes; used to limit
  a runner origin to its page and assets.

Node sites created before 1.18 keep their inline proxy until their nginx
configuration is next rendered (for example by `ssl install`); they then get
the same proxy from a generated routes file.
