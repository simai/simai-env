# simai-env v1.14.0

Release date: 2026-09-22

## Summary

simai-env can now run existing applications the way they describe
themselves, on PostgreSQL as well as MySQL, and explains itself to AI agents.

- **PostgreSQL.** `db pgsql-install` installs the Ubuntu version or a newer
  major from the PGDG repository (key pinned by fingerprint). Sites choose
  `--db-engine pgsql`; create, drop, rotate, `.env` export, doctor,
  healthcheck and `backup data` (`pg_dump` with restore test) follow the
  engine. Each site role owns only its database.
- **Application manifest.** `.simai/app.json` plus `composer.json` declare PHP
  version and extensions, OS packages, database engine, production env
  values, scheduler, migrations, workers and frame ancestors. Input is
  validated before the shell sees it; secrets are rejected.
- **`site adopt`** attaches an existing application without scaffolding:
  installs requirements, creates `.env` from `.env.example` only when
  missing, runs `composer install --no-dev` as the site user, generates
  `APP_KEY` once, migrates on request and writes the declared workers.
  Running it again reconciles.
- **`site deploy`** ships releases from a git ref, a checksummed archive or a
  directory: build and migrate before an atomic `current` switch, PHP-FPM
  reload, graceful `queue:restart`, `deploy-rollback`, retention.
- **Workers** from the manifest get one systemd unit per instance with a
  stop timeout long enough for long jobs.
- **`frame-policy origins:<list>`** allows embedding only by the listed
  origins.
- **AI-first.** `self describe`, `site describe` and `self commands` return
  JSON (no secrets). `AGENTS.md` tells an agent where to start; `self migrate`
  links it as `/root/AGENTS.md`.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update
```

Existing sites are unchanged. To attach an application:

```bash
sudo /root/simai-env/simai-admin.sh site adopt --domain app.example.com --path /home/simai/www/app.example.com
sudo /root/simai-env/simai-admin.sh site adopt --domain app.example.com --path /home/simai/www/app.example.com --confirm yes
```

## Behaviour changes

- Laravel env preparation keeps the application's `CACHE_STORE`,
  `SESSION_DRIVER` and `QUEUE_CONNECTION` and no longer forces
  `DB_CONNECTION=mysql`.
- The healthcheck reports `connection failed` instead of the driver message.
- The first `site deploy` moves an in-place site to the release layout
  (`releases/`, `current`, shared `.env` and `storage` in the site root);
  nginx then serves `current/<public>`.

## Verification

- repository CI on Ubuntu 22.04 and 24.04, including manifest validation and
  describe secret filtering;
- end-to-end in systemd containers on 22.04 (PostgreSQL 17 from PGDG,
  PHP 8.4) and 24.04 (PostgreSQL 16, PHP 8.4) with a real Laravel 13 app:
  adopt, migrations, scheduler, a long job across `queue:restart` finishing
  exactly once, deploy from directory and archive, failed deploy keeping the
  live release, rollback, backup of the live release only, PostgreSQL
  backup/restore, re-adopt keeping `APP_KEY`, describe without secrets;
- `testing/run-regression.sh full` (63 steps) on the regression host.

## Rollback

Restore the pre-update archive printed by `self update`. Sites already moved
to the release layout keep working on v1.13.0 only for serving; `site
deploy` and `site adopt` are not available there.
