# simai-env v1.20.0

Release date: 2026-10-28

## Summary

First stage of the gateway for SIMAI ENV Panel, a control panel built on
Larena that simai-env installs as an ordinary site. simai-env stays the only
component that changes the host; the panel asks it through one narrow entry:

```bash
sudo /root/simai-env/simai-admin.sh panel gate-enable --confirm yes
printf '%s' '{"schema":"simai-panel-request/1","request_id":"r1","actor":{"user":"me","owner":null},"command":"self:describe","args":{}}' \
  | sudo -u simai-panel sudo -n /usr/local/sbin/simai-panel-gate
```

- The `simai-panel` account may run only the gateway, without arguments; the
  request comes as JSON on stdin.
- Stage 1 is read-only: `self:describe`, `self:commands`, `site:describe`,
  `site:doctor`. Everything else is refused with a stable reason.
- `actor.owner` limits a request to that owner's sites; the host description
  is reduced to them.
- `--pubkey-file` opens the same gateway to an SSH key as a forced command,
  for a panel on another machine.
- Requests are logged as JSON lines in `/var/log/simai-panel-gate.log`.

The contract is in `docs/architecture/panel-gate.md`. Nothing changes on
hosts that do not run `panel gate-enable`.

For panel development, `testing/stand/stand.sh up` starts a local container
with demo sites and the gateway; `record` writes the gateway answers that
the panel replays to `testing/fixtures/panel/`.
