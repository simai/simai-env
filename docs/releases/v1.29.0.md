# simai-env v1.29.0

Release date: 2026-11-01

## Summary

**A static site can become a node site in place.** A site deployed as static
(GitHub Pages style) that now needs an API, such as votes stored on the
server, switches with one command and keeps its address, certificate and
releases:

```bash
sudo /root/simai-env/simai-admin.sh site set-profile --domain D --profile node              # plan
sudo /root/simai-env/simai-admin.sh site set-profile --domain D --profile node --confirm yes
sudo /root/simai-env/simai-admin.sh site deploy --domain D --git URL --ref TAG --confirm yes  # first node release
```

- The site gets a local port and the node vhost; HTTPS, HSTS, the HTTP to
  HTTPS redirect, path redirects and path rules carry over.
- Until the first node release, nginx serves the current static release
  exactly as before (`/dir/`, `/page`, `404.html`, caching, fonts). The switch
  is one nginx reload.
- The first release with `node.start` and `static.root` takes over; its
  `shared` paths (for example `state`) live in `<root>/shared` and are in the
  file backups.
- `deploy-rollback` to an earlier static release serves it and stops the
  service; `set-profile --profile static` then switches back.
- Any failure on the way puts back the previous configuration.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --confirm yes
```
