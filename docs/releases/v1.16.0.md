# simai-env v1.16.0

Release date: 2026-10-20

## Summary

Ubuntu 26.04 and long-running Node.js services. The release came out of
preparing a new host for the SIMAI icon service with simai-env alone: every
step that needed a hand edit became a command.

- **Ubuntu 26.04 LTS.** PHP 8.5 comes from the Ubuntu repository while
  ondrej/php has no packages for the release; other versions are refused with
  a clear message (they become installable once the PPA covers 26.04, without
  a code change). PHP 8.5 builds OPcache into the core, so no `php8.5-opcache`
  package is requested. PostgreSQL 18 is native. CI and the container suite
  run on 22.04, 24.04 and 26.04.
- **Lean hosts.** `bootstrap --php none --mysql none` (or
  `SIMAI_INSTALL_PHP=none SIMAI_INSTALL_DB=none` for `install.sh`) prepares a
  host without PHP or MySQL. The default PHP follows the release. apt waits
  for the dpkg lock that unattended-upgrades holds after the first boot.
- **Profile `node`.** `site add --profile node` allocates a local port and an
  nginx proxy. `site deploy` builds the release as the site user (yarn/npm,
  a Python venv from the manifest, an optional build), runs
  `simai-app-<project>.service` from `current` with restart on failure and
  on boot, checks the health path and returns to the previous release when
  it fails. `site service-restart`; `site describe` reports the service.
  New manifest fields: `node`, `python`, `shared`, `health`.
- **Host baseline commands.** `self swap-ensure`; `self firewall-ensure`
  (ufw: SSH, 80 and 443; the SSH port is detected and its rule verified before
  the policy is enabled; the plan lists listening services that would become
  unreachable; `--allow port/proto@source` keeps one), `self firewall-disable`.
- **Host settings.** `self settings` and `self setting-set` change allowlisted
  keys of `/etc/simai-env.conf`: `SIMAI_SITE_ISOLATION=no` keeps all new sites
  on the one `simai` account, `SIMAI_LOCK_WAIT`, `SIMAI_BACKUP_OFFSITE`.
- **Plans are back.** Commands registered with `plan:handler` (`site deploy`,
  `deploy-rollback`, `self swap-ensure`, `self firewall-ensure`) print their
  detailed plan without `--confirm yes` instead of the generic preview.
- **Fixes found on the new host.**
  - Since 1.15.0 the `self migrate` that `self update` runs was a silent
    no-op: the worker passed `SIMAI_SOURCE_ONLY` to child processes, so a
    handler that started `simai-admin.sh` again only loaded definitions.
    Nested calls dispatch again (covered by `dispatch_e2e`).
  - A confirmed deploy of a service site installs the apt packages its
    manifest declares, and `python3-venv` for Python requirements (fresh
    26.04 hosts do not have it; service sites have no adopt step).
  - `site remove` of a deployed site no longer keeps its metadata because of
    the deploy lock file; the deploy source is recorded on one line.
  - `self update` runs with a non-executable `update.sh` and continues from
    the new toolkit directory; apt waits for the dpkg lock after first boot;
    bootstrap installs `iproute2`.

## Update

```bash
sudo /root/simai-env/simai-admin.sh self update --confirm yes
sudo /root/simai-env/simai-admin.sh self migrate --confirm yes   # once, on hosts updated by 1.15.x
```

The second command runs the host migrations that the 1.15.x update handler
skipped; from 1.16.0 on `self update` runs them itself.

No configuration changes are required. The `node` profile is opt-in:
`simai-admin.sh profile enable --id node --confirm yes`.

## Verification

- CI on Ubuntu 22.04, 24.04 and 26.04: Bash syntax, ShellCheck, errexit lint,
  smoke and correction regressions, option validation and registry dispatch
  for all 169 commands.
- Container suite, 20 cases on each of Ubuntu 22.04, 24.04 and 26.04,
  including the new `node_e2e` (25 checks: port, proxy, build as the site
  user, managed PORT/HOST, venv, shared cache across releases, failed health
  check returns to the previous release, rollback, crash restart, describe,
  remove) and `host_e2e` (20 checks: native PHP without PPA, swap, firewall
  with SSH rule verification and exceptions, host settings and the shared
  account). On 26.04 the Laravel adopt/deploy cases run on PHP 8.5;
  `upgrade_e2e` is skipped there because 1.14.0 did not support 26.04.
- `testing/run-regression.sh full` on the regression host (Ubuntu 24.04),
  updated from 1.15.0: 63 checks.
- The new host for the SIMAI icon service (Ubuntu 26.04, 1 vCPU, 1.9 GB) was
  prepared and the service deployed with these commands only: install without
  PHP/MySQL, 2 GB swap, ufw with the hosting monitoring exception, one shared
  site account, `site add --profile node`, `site deploy` from git. The
  service returns the same `X-SIMAI-Font-Hash` as production
  (`e740ac3c…`, mode `static-weight`) and survives a reboot.

## Rollback

Restore the pre-update archive printed by `self update`. Node sites created
with 1.16.0 need 1.16.0 for deploys; their services keep running after a
rollback.
